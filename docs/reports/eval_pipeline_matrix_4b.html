Qwen3-VL-4B 评测口径矩阵

同一批 checkpoint 在不同评测 pipeline/参数下的分数对照，用于判断"哪个口径可信、跨口径能不能比、以后统一怎么评"。全部数据来自 2026-07-13 ~ 07-16 的实测（trial 301783374 等）。核心结论见页尾。

口径定义

P0 官方论文：Vision-OPD 论文报告数字。官方 mm-eval 代码，temp=0.7/top_p=0.8/top_k=20/pp=1.5/max_tokens=8192，AutoProcessor max_pixels=16.7M（不缩图），prompt 为 "<问题> Select from the following choices.\n(A)…"（诱导先推理再作答），judge=Qwen3-30B。
P1 官方代码复刻：同一套官方代码+参数+seed42，唯一差异 judge 换成 Azure GPT（gpt-5.4）。
P2 VLMEvalKit 默认：本仓库主口径。server 模式，temp=0/pp=1.5/max_tokens=4096，MCQ prompt 末尾带"Please select the correct answer…"（诱导直接吐字母），GPT judge。ZoomBench 走 canonical 原生管线（v3-fixed judge）。
P3 VLMEvalKit+官方采样：P2 基础上把采样参数全部对齐官方（temp0.7/pp1.5/8192/16.7M px），prompt 仍是直答风格。
P4 VLMEvalKit+官方prompt：P3 基础上再把 MCQ prompt 换成官方风格（VLMEVAL_MCQ_OFFICIAL_STYLE=1，2026-07-16 新增开关）。

结论：哪个可信、以后怎么评

1. 官方数字是真实的。官方代码+官方 checkpoint 完整复现（V*/HRBench ±0.5pp，其中 base HRBench4K 一位不差），没有灌水。
2. 分差三大来源已全部定位：prompt 风格（直答 vs 带内容作答，HRBench 上最大 ~5pp、且影响大小与模型相关）＞ judge 模型（ZoomBench 上 ~5pp 一致偏移）＞ 采样参数（~1pp）。图像分辨率处理曾被怀疑、已排除（checkpoint 默认就是 16.7M 上限，两条管线图像保真度等价）。
3. 以后怎么评（建议）：(a) 组内比较（自己的模型互相比、比 base）：继续用 P2（VLMEvalKit 默认，temp0 可复现、历史数字全在这个口径）；(b) 和官方论文数字对表：用 P1（官方代码）或 P4（VLMEvalKit + VLMEVAL_MCQ_OFFICIAL_STYLE=1 + 官方采样），ZoomBench 例外——用我们的 canonical 管线（它和 P0 最接近）；(c) 论文里引用任何跨口径数字必须标注 pipeline/prompt/judge 三要素。
4. 不要做的事：把 P2 的 HRBench 数字和官方论文表并排比较（会把 VisionOPD 系的方法系统性低估 ~5pp）；在 temp0.7 无 seed 下跑小样本 benchmark（V*Bench n=191 单次方差 ±2.8pp）；引用 HRBench 数字前不查 eval_integrity_registry.md（API 失败污染史）。
