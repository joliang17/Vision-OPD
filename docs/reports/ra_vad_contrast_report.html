对比锐化蒸馏 Target：2B 结果报告

把 RA-VAD 自蒸馏的 target 从纯 EMA teacher 分布换成对比锐化分布—— softmax(log phi + α·(log phi − log pctrl))—— 把一个趋近于零的 teacher-student 信号变成了这套机制第一次真正的学习曲线，也是第一个 同时在 ZoomBench 上超过原始 base 模型和 GRPO 的 RA-VAD 变体。

模型 Qwen3-VL-2B-Instruct EMA 自蒸馏，无 RL reward 62 步 / 1 epoch black-image ctrl 2026-07-10 → 07-12

机制

从标量权重到蒸馏 target 本身

RA-VAD 是纯自蒸馏：EMA teacher（student 权重的滑动平均）通过 KL 散度蒸馏给 student，全程没有外部更强 teacher、没有 ground-truth 标签，也没有 RL reward——reward_model.enable=False 贯穿始终。

Teacher 会看到同一个 prompt 的两个版本：hi（真实图像）和 ctrl（同尺寸的黑图）。两者的差 log phi − log pctrl 是整条 pipeline 里唯一能说明"这个 token 是不是真的依赖图像"的信号。原始设计把这个差值 当作一个标量权重，加在一个原本平平无奇的蒸馏 target 上。根因诊断（Phase 2-核心 第十轮）发现：EMA teacher 和 student 太接近，几乎处处一致——这个差值一直在给一个几乎不 存在的信号做加权。

原始 target —— 纯 EMA hi 分布
L = Σt wt · KL( phi,t ‖ pstudent,t ) / Σt wt
wt 由逐行 clip + 归一化后的 log phi − log pctrl 得到。 在权重最高的十分位上实测 teacher-student KL 只有 0.0007 nats—— 比同一批 token 上 teacher 自己的 hi-vs-ctrl 差距小了约 1800 倍。
（2026-07-16 修正公式书写方向：代码实际是 forward KL——target 在前， F.kl_div(student_logp, teacher_logp, log_target=True) = KL(teacher‖student)， `ra_divergence_alpha=0.0`；本报告此前把两个分布的顺序写反了，数值和结论不受影响。）
对比锐化 target
target = log_softmax( log phi + α·(log phi − log pctrl) ) ，  限制在 { w : phi(w) ≥ β·max phi } 内
数学上等价于几何倾斜 phi1+α / pctrlα—— 相当于把推理期的 contrastive decoding 操作蒸馏进了训练。四重保护保证安全： softmax 保证永远是合法分布；β-plausibility 掩码把支撑集限制在 hi 本来就认可的 token 子集；exclude_token_ids 防止 <|im_end|>/<|endoftext|> 被意外拔高；可选的 position gate 把干预限制在真正有 RA-weight 证据的位置。

★ αc=0 matched baseline（07-20 立项，方法的关键隔离对照）：把上式 α 取 0， target 退化为 log_softmax(log phi) 限制在同一 plausibility set 内——即 纯温度软化的 EMA-teacher 自蒸馏，没有任何对比锐化。这个 baseline 与终局 ours 逐项完全一致 （uniform 无 wt / β=0.1 mask / EOS 豁免 / forward-KL / EMA / unfiltered / 90 步 / len6144）， 唯一变量就是 tilt 项，所以 ours − (αc=0) 的差 = 对比锐化本身的净贡献， 比 reweight 对照更干净地回答"对比到底有没有用"。validator 已放宽允许 α=0（α<0 仍拒）。 🏃 2B 训练已排队（本地 8 卡，等当前 eval 腾卡后 fresh 启动），出数后回填此处 + 主表。
终局 loss（uniform）——response token 上的朴素掩码平均
L = Σt maskt · KL( targett ‖ pstudent,t ) / Σt maskt
（历史含权形式 L = Σ wt·KL / Σ wt，终局取 wt=maskt 即退化为上式）
target_mode=contrast 换掉的是 student 被拉向的目标；外层曾经还有一层逐 token 权重 wt，但终局配置已把它取成 wt=maskt（uniform）， loss 就是 response token 上的普通掩码平均，公式里不再出现 wt。 为什么能去（07-18/07-20 定稿）：逐 token 权重 wt 被证明是非承重、可去掉的 inherited 组件 ——len 对齐后三个 scale 的 uniform vs weighted 差全在噪声带 （2B +0.33 / 4B −0.69 / Qwen3.5 +0.29），故终局直接采用 uniform（无 wt、无 gate）。 因此 wt reweight 对照不再是本方法的关键 baseline； 真正 matched 的关键 baseline 是 αc=0（见下方 contrast target 卡片）——它保持 uniform / β mask / EOS 豁免 / forward-KL / EMA 全部一致，仅把 tilt 项关掉，直接隔离"对比锐化本身"的净贡献。
同样是 forward KL（target 在前），方向由 ra_divergence_alpha 控制：0=forward（本报告所有 contrast 实验的实际取值）、 1=reverse KL（KL(student‖target)，VA-OPD 论文以及多数蒸馏工作用的方向）、0.5=generalized JSD。 KL 方向消融（reverse vs forward vs JSD）已排入队列，在 Qwen3-VL-4B × virl39k 上跑。
wt 具体怎么算的 —— compute_ra_weights()，verl/trainer/ppo/ra_vad.py
at = (log phi − log pctrl)t · maskt
at+ = relu(at − δ)  (δ = ra_delta，默认 0)
ât = min( at+ , cliprow )  (cliprow = 同一条 rollout 内 a+ 正值集合的 95% 分位数，ra_clip_quantile)
w̃t = ât / meanrow(â | â>0)  (正值 token 数 < min_positive_tokens 时整行记 0)
gsample = σ(margin / 0.5) · σ(ra_answer / 0.1)  (margin = meanrow(at)，ra_answer = meanrow(w̃t | 正值 token)；no_sample_gate=True 时 g=1)
wt = stopgrad( w̃t · gsample ) · maskt
五步流水线：① 原始信号（teacher 在 hi/ctrl 两种条件下同一个 token 的 logprob 差）； ② 加 δ 阈值只留正的部分（δ=0 时等价于纯 relu）；③ 按 rollout 逐行裁剪掉 95 分位以上的极端值， 防止个别离群 token 主导整行权重；④ 除以本行正值均值做归一化，让每条 rollout 内部的权重量级可比； ⑤ 再乘一个"整条 rollout 是否值得学"的样本级门控——如果这条 rollout 平均的 hi/ctrl 差距很小 （margin 低）或者归一化后的"回答质量"信号很弱（ra_answer 低），整条 rollout 的权重会被 sigmoid 压得接近 0，而不是逐 token 判断。全程 stopgrad（.detach()）， wt 本身不参与反传，只是给 KL loss 做加权系数。ra_uniform_weight=True 时跳过整条流水线，直接 wt=maskt——对应上面提到的隔离实验。

⚠️ 历史结论已被推翻（保留作过程记录）：2026-07-14 的首个隔离实验（62 步、filtered 数据） 曾得到 uniform-weight 比带权重低 2.09pp（68.56 vs 70.65），当时据此判"外层权重是必要成分"。 但该结论在 07-18/07-20 被系统性推翻：那 2.09pp 是 repo/filtered 数据 + 短程 62 步的 数据依赖假象；换到终局口径（virl39k、len 对齐、90 步）后三个 scale 的 uniform vs weighted 差全部落进 噪声带（2B +0.33 / 4B −0.69 / Qwen3.5 +0.29，见消融 C）。「wt 必要」与「uniform 严格更好」 两个方向的强 claim 都不成立，wt 最终定性为无显著作用的 inherited 组件，终局配置取 uniform。 reweight 因此退出方法叙事——关键隔离对照改由 αc=0 matched baseline 承担。

不是 attention weight：raw signal 默认就是上面这个 logprob 差，本报告里的所有实验 都没传过 ra_weight_source，走的都是这条默认路径。代码里另外留了一个 attention_to_image_score() 函数，可以通过 ra_raw_override 换成"attention 集中在图像 token 上的程度"作为 raw signal （需要显式设 ra_weight_source="attention"），但这条路径从没在任何一次 训练里被启用过，纯粹是代码里预留的可扩展点，跟本报告的结果无关。

为什么 contrast 的 loss 后段会回涨？

Contrast target 不是一个固定标签，而是相对当前 EMA teacher 现算出来的—— target = softmax(log phi + α·(log phi − log pctrl))， 而 phi 本身就是 student 权重的滑动平均。训练早期 student ≈ teacher ≈ base 模型，target 只是把一个温和分布轻微倾斜，student 很容易追上，loss 快速下降（下图前 100–150 步都是单调降）。但每一步 student 都被推向"比当前 teacher 更极端"的分布，teacher 又是 student 的 EMA， 于是这是一个自我放大的反馈环：student 更尖锐 → teacher 随之更尖锐 → 下一步的 target 在一个已经更尖锐的 teacher 基础上继续加码。62 步的本仓库训练（上图）还没跑到这个环路失控的阶段，loss 一直在降；virl39k/sr1 上训到 300+ 步，用零成本的 rollout-dump 扫描已经确认生成质量的崩溃（中英混杂、无限复读） 恰好从 step 150–200 开始，和下图 loss 转头上升的位置基本对上——student 的真实输出分布 已经脱离了任何"合理语言分布"的范围，越来越难用 KL 去逼近一个同样在漂移、且越来越极端的 target， loss 因此不降反升。GRPO(virl39k) 的 pg_loss 全程没有这种单调爬升（它的 target 是标量 reward， 不存在这种自我强化的分布漂移），和它没出现生成崩溃的观测一致。 2026-07-14 更新：这个假设已经验证——把 contrast-标准×virl39k 截短到 90 步重训， 7-bench 恢复到 70.68（对照本仓库数据 62 步的 70.65），ZoomBench/POPE/HallusionBench 全部正常， 没有任何复读/中英混杂迹象（详见下方 Benchmark 结果表 §§ 脚注）—— 训练长度确实是崩溃的直接原因，安全区上限比最初猜测的 62 步更宽，但边界确实存在于 90～437 步之间。

90 步短训重跑组（2026-07-14/15，安全区内的完整曲线）——同样四个 contrast × 外部数据 组合，截短到 90 步重训（上图崩溃版的修复实验）。四条曲线全程健康下降、没有出现上图 150 步后的回涨， 与下游 benchmark 全部正常（69.3-70.7）互相印证。注意两条 sr1 曲线用的是 MAX_PROMPT_LENGTH=4096 （virl39k 是 6144，为绕开 sr1 数据在该配置下的 OOM），loss 绝对值因此不能跨数据集直接比较， 只看各自趋势。数据来源：各训练日志的 actor/vopd_loss，无平滑。

哪些真的动了，哪些没动

contrast-标准是第一个在 HallusionBench 上超过 base 的变体

69.19 对 68.35（+0.84）。此前所有 RA-VAD 变体——noimg、纯 EMA、attention 加权——在这项指标上相对 base 全部倒退。这是机制设计初衷本该起作用、却一直没兑现的那个维度。

MathVista_MINI 是单项提升幅度最大的 benchmark

67.90 对 noimg 的 63.20（+4.7），对 base 的 62.50（+5.4）——比 GRPO 自己用 9.4 倍算力换来的 MathVista 增量（+5.5 相对 base）还要大。这促成了现在正在跑的 virl39k-filtered 后续实验，用来判断这是机制本身的能力还是训练数据本身偏 math。

MMBench_DEV_EN 是 contrast 仍然落后 base 的地方

77.06 对 78.09——约 1pp 的退步，所有测过的 RA-VAD 变体都有,不是 contrast 独有也没被 contrast 修复。这一点应该如实标出来,不该被"全项胜出"这种概括盖过去。

ZoomBench 这一列口径不统一

2B baseline / GRPO / contrast-标准走的是最新 canonical GPT-judge pipeline；VisionOPD 和 4B 全系都还是 v3-fixed native pipeline 的历史数字，两套 judge 设置不完全一致。contrast-保守和 4B 全系的 ZoomBench 都还没跑，这一列现在还不能直接横向比较。

4B 上 contrast-保守反而比标准版更稳

7-bench 平均 77.09 对 76.58，和 2B 上"标准 > 保守"（70.65 vs 69.07）方向相反。4B 标准版在 MMBench_DEV_EN 上明显回落（80.15，全表 4B 组最低），α=1.0 的更强倾斜在 4B 规模上似乎不再是越强越好。

数据消融 —— 换 math-heavy 训练数据（2026-07-13，进行中）

同一机制换到 virl39k / sr1 数据上会怎样

动机：contrast 机制在 MathVista_MINI 上提升最大，但本仓库训练数据不偏 math。把 GRPO 和 contrast-保守/标准分别换到 virl39k-filtered（几何/图表 MCQ 为主，14002 条单图样本）和 vision-sr1-filtered（通用 VQA，14355 条）上重训（各 1 epoch，~437-464 步），看 MathVista 的增益到底来自机制还是数据题材。对应的行已经并入上面的 2B 总表（按训练数据分组）， loss 曲线见上方"训练动态"两张图的下面一张，这里只放定性结论。

GRPO 换 math 数据：综合分升，ZoomBench 大跌

7-bench 71.66（比本仓库数据的 70.19 高 1.47，且只用了 1/3 的算力），MathVista 68.70 也略高。但 ZoomBench 从 47.81 暴跌到 38.34（-9.5pp）——GRPO 的 ZoomBench 优势强依赖训练数据分布，不是机制自带的。

contrast-保守：换数据后 ZoomBench 差异不大

virl39k(40.36) 和 sr1(40.00) 基本打平，都略低于 noimg-virl39k 的 41.54 和 2B base 的 42.49。MathVista 是否有本仓库数据版本(65.30)之上的提升，等 7-benchmark 跑完揭晓——这是数据消融的核心问题。

另一个新发现：GRPO(virl39k) 的 HallusionBench 明显好于 GRPO(本仓库)

aAcc 68.45 vs 66.14（+2.31），qAcc 47.03 vs 43.30——GRPO 的幻觉表现同样受训练数据影响很大，之前"GRPO 幻觉指标全面低于 base"的结论只对本仓库数据成立。

同时在跑的还有（结果未出）：4B base 全 9 项基线重测（GPU4，顺带解决文档里 4B base 7-bench 两组数字不一致的问题）、 visionopd-4B 和 grpo-4B 的 POPE/HallusionBench 补测（GPU5/6）。 uniform-weight 隔离实验已出结果（2026-07-14）：7-bench 68.56 vs 带权重的 70.65（−2.09pp，超出种子噪声带），结论是外层逐 token 权重仍是必要成分——详见上文 "从标量权重到蒸馏 target 本身"一节的更新说明。
